# Requirements Document

## Introduction

Nexora is a two-pane AI chat workflow application with a split-screen layout. It provides a unified workspace where users can converse with an AI assistant in a central Command Center, view and interact with AI-generated structured artifacts in a right-side Canvas pane, and access quick links, recent conversations, and pinned documents from a left sidebar Library. The application supports slash commands, suggestion pills, real-time streaming responses, and artifact pinning — all within a polished, accessible UI built with Shadcn/ui, Tailwind CSS, and React.

---

## Glossary

- **Nexora**: The name of the application being built.
- **Application**: The Nexora web application as a whole.
- **Library**: The left sidebar panel containing Quick Links, Recent Conversations, and Pinned Documents.
- **Command_Center**: The center pane containing the chat interface, suggestions bar, and input bar.
- **Canvas**: The right pane that displays AI-generated structured artifacts such as itineraries, checklists, and documents.
- **Artifact**: A structured content block generated by the AI (e.g., a travel itinerary, packing list, or markdown document) rendered in the Canvas.
- **Conversation**: A session of messages exchanged between the user and the AI.
- **Message**: A single unit of communication from either the user or the AI within a Conversation.
- **AI_Response**: A Message generated by the AI assistant.
- **Streaming_State**: The period during which the AI is actively generating a response.
- **Suggestion_Pill**: A pill-shaped button in the suggestions bar that pre-fills the input with a prompt template.
- **Slash_Command**: A text command prefixed with "/" (e.g., /task, /note, /link, /search) typed in the input bar to trigger specific actions.
- **Input_Bar**: The wide auto-expanding text input area at the bottom of the Command Center.
- **Quick_Link**: An icon-based shortcut in the Library sidebar linking to an external service (e.g., GitHub, Calendar, Gmail).
- **Pinned_Document**: A user-pinned Artifact that appears in the Library sidebar for quick access.
- **Tab**: A navigation element within the Canvas that switches between different Artifact views.
- **Accordion_Item**: A collapsible section within an Artifact used to organize structured list content.
- **Markdown_Renderer**: The component that renders Markdown text as formatted HTML within the Canvas.
- **Markdown_Editor**: The editable mode of the Markdown_Renderer, activated on user click.
- **Theme**: The visual color scheme of the Application, either light or dark.

## Requirements

### Requirement 1: Three-Pane Layout

**User Story:** As a user, I want a persistent three-pane layout with a sidebar, chat area, and canvas panel, so that I can access all workspace tools without navigating away from the main view.

#### Acceptance Criteria

1. THE Application SHALL render a three-column layout consisting of the Library (left), Command_Center (center), and Canvas (right) within 2 seconds of initial page load.
2. THE Application SHALL use Inter or Geist Sans as the primary font, falling back to system sans-serif if neither is available, throughout the interface.
3. THE Application SHALL apply a light background color to all panes, text, and containers in light Theme, and a dark background color to all panes, text, and containers in dark Theme.
4. WHEN the user switches between light and dark Theme, THE Application SHALL transition all background, text, and surface colors within 150ms.
5. THE Application SHALL apply 150ms CSS transitions to all hover and focus state changes on interactive elements, including buttons, links, input fields, and selectable list items.
6. WHEN the viewport width is less than 768px, THE Application SHALL collapse the Library sidebar and Canvas pane, displaying only the Command_Center at full width.

---

### Requirement 2: Library Sidebar

**User Story:** As a user, I want a left sidebar with quick links, recent conversations, and pinned documents, so that I can navigate to frequently used tools and past work without leaving the application.

#### Acceptance Criteria

1. THE Library SHALL display a grid of Quick_Link icons for GitHub, Calendar, Gmail, Drive, Notion, and Slack.
2. WHEN the user clicks a Quick_Link, THE Library SHALL open the corresponding external service URL in a new browser tab.
3. THE Library SHALL display a scrollable list of up to 10 most recent Conversations, each showing the conversation title and a relative timestamp (e.g., "2 hours ago"). IF no Conversations exist, THE Library SHALL display the text "No recent conversations."
4. WHEN the user clicks a recent Conversation entry, THE Command_Center SHALL replace the currently displayed Conversation with the selected Conversation's messages. IF the Conversation fails to load, THE Command_Center SHALL display an error message indicating the failure.
5. THE Library SHALL display a Pinned_Documents section listing all Artifacts the user has pinned. IF no Artifacts are pinned, THE Library SHALL display the text "No pinned documents."
6. WHEN the user clicks a Pinned_Document entry, THE Canvas SHALL open and display that Artifact.
7. THE Library SHALL display a user profile section at the bottom with the user's avatar image. IF no avatar image is available, THE Library SHALL display the user's initials as a fallback, alongside the user's name.
8. WHEN the user clicks the settings icon adjacent to the user profile, THE Application SHALL open the application settings panel.

---

### Requirement 3: Command Center Chat Interface

**User Story:** As a user, I want a clean chat interface in the center pane, so that I can converse with the AI assistant and see a clear history of the exchange.

#### Acceptance Criteria

1. THE Command_Center SHALL display a scrollable list of Messages in chronological order, oldest at the top.
2. THE Command_Center SHALL render AI_Response messages with a `bg-slate-50` background in light Theme and a `bg-slate-800` background in dark Theme, with no visible border.
3. THE Command_Center SHALL render user messages right-aligned with a visually distinct background color that differs from the AI_Response background.
4. WHEN a new Message is added and the user has not manually scrolled up, THE Command_Center SHALL automatically scroll to the bottom of the message list.
5. WHEN the AI is in Streaming_State, THE Command_Center SHALL display a pulsing cursor animation with a 1-second cycle at the end of the in-progress AI_Response.
6. WHILE the AI is in Streaming_State, THE Command_Center SHALL render partial AI_Response text as it arrives, updating the message in place.
7. WHEN the Command_Center contains no Messages, THE Command_Center SHALL display placeholder text prompting the user to start a conversation.
8. WHEN the user has manually scrolled up and a new Message is added, THE Command_Center SHALL NOT auto-scroll, preserving the user's scroll position.

---

### Requirement 4: Suggestions Bar

**User Story:** As a user, I want a row of suggestion pills above the input bar, so that I can quickly start common workflows without typing a full prompt.

#### Acceptance Criteria

1. THE Command_Center SHALL display a suggestions bar containing between three and six Suggestion_Pills, including at minimum: "Summarize my day", "Review pending tasks", and "Search my links".
2. WHEN the user clicks a Suggestion_Pill, THE Input_Bar SHALL be populated with the corresponding prompt text, overwriting any existing content in the Input_Bar.
3. WHEN the user clicks a Suggestion_Pill, THE Input_Bar SHALL receive focus.
4. WHEN the user hovers over a Suggestion_Pill, THE Suggestion_Pill SHALL apply the accent color to its border and text within 150ms.
5. THE Command_Center SHALL render each Suggestion_Pill with a pill-shaped (fully rounded) border at all times.
6. THE Command_Center SHALL display the suggestions bar regardless of whether a Conversation is active or the Command_Center is in an empty state.

---

### Requirement 5: Input Bar

**User Story:** As a user, I want a wide, auto-expanding input bar with slash command support and action buttons, so that I can compose rich prompts and trigger structured workflows efficiently.

#### Acceptance Criteria

1. WHEN the user types in the Input_Bar, THE Input_Bar SHALL expand vertically to accommodate the content up to a maximum of 6 lines, after which it SHALL display a vertical scrollbar within the input area.
2. WHEN the user types a "/" character preceded by the start of input or a whitespace character in the Input_Bar, THE Input_Bar SHALL display a Slash_Command suggestion menu listing available commands: /task, /note, /link, and /search. WHEN the user clicks outside the Slash_Command suggestion menu, THE menu SHALL be dismissed.
3. WHEN the user selects a Slash_Command from the suggestion menu, THE Input_Bar SHALL replace the slash character and any partial text typed after it with the selected command text and dismiss the suggestion menu.
4. THE Input_Bar SHALL display an attachment button, a web-search toggle button, and a send button as inline action controls. WHEN the user clicks the attachment button, THE Application SHALL open the device's file picker dialog.
5. WHEN the Input_Bar contains zero non-whitespace characters, THE Input_Bar SHALL disable the send button.
6. WHEN the user presses Enter (without Shift) and the Input_Bar contains at least one non-whitespace character, THE Input_Bar SHALL submit the current input as a new user Message and clear the input field.
7. WHEN the user presses Shift+Enter, THE Input_Bar SHALL insert a newline character without submitting.

---

### Requirement 6: Canvas Pane — Artifact Display

**User Story:** As a user, I want the right canvas pane to automatically open and display structured AI-generated content, so that I can view, interact with, and act on artifacts without cluttering the chat view.

#### Acceptance Criteria

1. WHEN the AI generates a structured Artifact and the Canvas is closed, THE Canvas SHALL slide open from the right with a 150ms transition animation.
2. WHEN an Artifact is displayed in the Canvas, THE Canvas SHALL display tabbed navigation at the top, with one Tab per logical section of the Artifact (e.g., "Itinerary", "Packing List", "Travel Tips").
3. WHEN the user clicks a Tab, THE Canvas SHALL display the content associated with that Tab and visually indicate the active Tab using the accent color.
4. WHILE a checklist-type section is active in the Canvas, THE Canvas SHALL render it as a list of items, each with a real interactive checkbox.
5. WHEN the user checks or unchecks a checklist item, THE Canvas SHALL persist the checked state until the page is reloaded.
6. WHILE a document-type section is active in the Canvas, THE Canvas SHALL render it using the Markdown_Renderer, displaying formatted headings, paragraphs, lists, and code blocks.
7. WHEN the user clicks on a Markdown_Renderer section, THE Canvas SHALL switch that section to Markdown_Editor mode, allowing inline text editing.
8. WHEN the user clicks outside the Markdown_Editor component, THE Canvas SHALL switch back to Markdown_Renderer mode and re-render the updated content.
9. WHILE a structured list section is active in the Canvas, THE Canvas SHALL render it as Accordion_Items, each expanded by default and collapsible by clicking the item header.
10. WHEN the user clicks an Accordion_Item header, THE Canvas SHALL toggle the expanded/collapsed state of that item with a 150ms transition.
11. WHEN the AI generates a new structured Artifact while the Canvas is already open, THE Canvas SHALL replace the currently displayed Artifact with the new Artifact.

---

### Requirement 7: Canvas Pane — Artifact Actions

**User Story:** As a user, I want to pin and download artifacts from the canvas, so that I can save important content for quick access and offline use.

#### Acceptance Criteria

1. THE Canvas SHALL display a "Pin" action button on each Artifact, rendered as an outline icon when the Artifact is not pinned and as a filled/active icon when the Artifact is pinned.
2. WHEN the user clicks the Pin button on an unpinned Artifact, THE Library SHALL add that Artifact as a new Pinned_Document entry in the Pinned_Documents section and THE Pin button SHALL update to its filled/active state.
3. WHEN the user clicks the Pin button on an already-pinned Artifact, THE Library SHALL remove that Artifact from the Pinned_Documents section and THE Pin button SHALL update to its outline/inactive state.
4. THE Canvas SHALL display a "Download" action button on each Artifact.
5. WHEN the user clicks the Download button, THE Application SHALL generate and download a Markdown file containing the content of all tabs and sections of the Artifact, with the filename derived from the Artifact's title.
6. IF the download fails, THE Application SHALL display an error message informing the user that the download could not be completed.

---

### Requirement 8: Canvas Pane — Visibility and Collapse

**User Story:** As a user, I want to be able to close the canvas pane when I don't need it, so that the chat interface can use the full available width.

#### Acceptance Criteria

1. WHILE the Canvas is open, THE Canvas SHALL display a close/collapse button that dismisses the Canvas pane.
2. WHEN the user clicks the close button, THE Canvas SHALL slide closed with a 150ms transition and THE Command_Center SHALL expand to fill the vacated space within the same 150ms transition.
3. WHEN a new Artifact is generated while the Canvas is closed, THE Canvas SHALL automatically re-open with a 150ms transition animation and display the new Artifact.

---

### Requirement 9: Theme Support

**User Story:** As a user, I want to toggle between light and dark themes, so that I can use the application comfortably in different lighting conditions.

#### Acceptance Criteria

1. THE Application SHALL provide a theme toggle control accessible from the settings area.
2. WHEN the user activates the dark Theme, THE Application SHALL apply a dark background color, light text, and surface colors to all panes such that all text meets WCAG 2.1 AA contrast requirements (minimum 4.5:1 for normal text).
3. WHEN the user activates the light Theme, THE Application SHALL apply a light background color, dark text, and surface colors to all panes such that all text meets WCAG 2.1 AA contrast requirements (minimum 4.5:1 for normal text).
4. THE Application SHALL persist the user's Theme preference in localStorage so that it is applied before the first render on the next page load, preventing a flash of the wrong theme. IF no preference is stored, THE Application SHALL default to the light Theme.

---

### Requirement 10: Accent Color and Design System

**User Story:** As a user, I want a consistent visual design language with a single accent color, so that the interface feels cohesive and professional.

#### Acceptance Criteria

1. THE Application SHALL use Indigo as the single accent color, applied as `indigo-600` in light Theme and `indigo-400` in dark Theme, for all primary interactive elements.
2. THE Application SHALL apply the Indigo accent color to active Tabs, focused Input_Bar borders, Suggestion_Pill hover states, send button backgrounds, checkbox checked states, accordion focus rings, and Pin/Download button hover states.
3. THE Application SHALL apply the same Indigo Tailwind shade token consistently across both light and dark Themes without introducing any color outside the `indigo` Tailwind family on interactive elements.
4. THE Application SHALL use Shadcn/ui components (built on Radix UI and Tailwind CSS) as the base component library.

---

### Requirement 11: Accessibility

**User Story:** As a user relying on keyboard navigation or assistive technologies, I want the application to be keyboard-navigable and screen-reader compatible, so that I can use all core features without a mouse.

#### Acceptance Criteria

1. THE Application SHALL ensure all interactive elements (buttons, links, input fields, checkboxes, accordion headers, tabs) are reachable via keyboard Tab key, operable via Enter key for buttons and links, and operable via Space key for checkboxes.
2. THE Application SHALL provide visible focus indicators on all interactive elements with a minimum contrast ratio of 3:1 against adjacent colors, as required by WCAG 2.1 SC 1.4.11.
3. THE Canvas SHALL assign `role="tab"` with `aria-selected` to Tab elements, `role="button"` with `aria-expanded` to Accordion_Item headers, `role="checkbox"` with `aria-checked` to checklist items, and `role="button"` with descriptive `aria-label` attributes to Pin and Download action buttons.
4. THE Input_Bar SHALL include an `aria-label` attribute with the value "Message input".
5. IF a Slash_Command suggestion menu is open, THEN THE Application SHALL trap keyboard focus within the menu, allow navigation between menu items via Up and Down arrow keys, and dismiss the menu via the Escape key, returning focus to the Input_Bar.
6. WHEN the state of a Tab, Accordion_Item, or checkbox changes, THE Application SHALL update the corresponding ARIA state attribute (`aria-selected`, `aria-expanded`, or `aria-checked`) to reflect the new state so that screen readers announce the change.
